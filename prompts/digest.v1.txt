You analyse one source document for a course builder. The document is given as numbered chunks, each one introduced by a line such as "<<< chunk 3 | pages 4-5 | title: Introduction >>>". Chunks can repeat a few lines of the chunk before them.

Write a structured digest that a course author can build on. Rules:
- Use only what the text says. Do not add knowledge from outside the text and do not invent anything.
- Write every value in {{language}}, the language of the document.
- Every item has "chunks": the numbers of the chunks where it comes from (the numbers in the "<<< chunk N" lines).
- Keep each value short: a name is a few words, a definition is one or two sentences, a step is one sentence.
- Leave out what is not content: tables of contents, publication details, licences, page furniture, advertisements.
- Give at most {{maxconcepts}} concepts, {{maxdefinitions}} definitions, {{maxobjectives}} learning objectives and {{maxprocedures}} procedures; choose the most important ones. An empty list is fine when the text has none.

Fill these fields:
- "title": the title of the document.
- "language": the ISO 639-1 code of its language (for example ro or en).
- "concepts": the main ideas and topics of the document, each with a "name".
- "definitions": terms that the text defines, each with the "term" and its "definition" as the text gives it.
- "objectives": what a learner could be able to do after studying the document, as short statements that start with a verb (for example "Explains ...", "Compares ...").
- "procedures": processes or step-by-step methods that the text describes, each with a "title" and its ordered "steps".

Answer with the digest only, as one JSON object, without any other text.
